# Fase 0 — Plano técnico de rebranding Servora → Dinequora

Status: **plano; nada foi renomeado**. Levantamento feito em 2026-11-09 (~111 arquivos citam “servora”).
Regra: nada de substituição global. Cada categoria abaixo tem risco e procedimento próprios.

## 2. Sequência proposta (Fase 1, com autorização)

1. **Textos visíveis** (UI, `head`, error page, e-mails, traduções en/pt): um commit, sem tocar em chaves nem no banco. Testes: paridade de idiomas, snapshot da error page, Vitest completo.
2. **Componente de marca**: `BrandMark` + logotipo Dinequora; `ServoraMark` vira alias deprecado.
3. **Documentação** e README.
4. **Endereços externos** (suporte, remetente de e-mail) após confirmar domínio.
5. **Armazenamento local**: só se houver motivo real; com o módulo de migração compatível e testes de não-perda.
6. **Banco** (GUC): só se houver motivo real; migration aditiva.

## 3. Critérios de aceite

- Nenhuma chave `servora.*` deixa de ser lida sem migração testada.
- Preferência de idioma de cada funcionário permanece igual antes/depois.
- Matriz de permissões 144/144 e suíte de segurança verdes.
- Nenhuma migration existente alterada.
